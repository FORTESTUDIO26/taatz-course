# taatz-course
אתר קורס קציני משא״ן ע״צ – מרכז תע״ץ

## מבנה
| תיקייה | מה יש בה | עולה ל-GitHub? |
|---|---|---|
| `docs/` | האתר עצמו (מתפרסם ב-GitHub Pages) | כן |
| `docs/content/demo-data.json` | התוכן ההתחלתי (מחזורים ו׳ ו־ז׳, לו״ז, רשימת מצגות) | כן |
| `supabase/schema.sql` | מבנה מסד הנתונים וההרשאות | כן |
| `supabase/seed.sql` | הזנת התוכן ההתחלתי (נוצר מ-demo-data.json) | כן |
| `supabase/migrations-*.sql` | שדרוגים למסד נתונים שכבר הוקם (כבר כלולים ב-schema.sql) | כן |
| `tools/` | בדיקות ושרת מקומי | כן (בלי node_modules) |
| כל השאר בתיקייה (מצגות, תמונות מקור, ייצוא PDF) | חומרי המקור | **לא** — חסום ב-`.gitignore` |

## מודל הגישה
* **ציבורי, ללא התחברות:** לו״ז המחזור הפעיל, מצגות, חוברות, ספר, מילון, מבחן, משוב ודף ״טופס סיום קורס״.
  קבצי החומרים נשמרים בדלי `materials` שפתוח לקריאה בלבד (בלי רשימת קבצים).
* **מבחן:** שם מלא, יחידה ומספר ת״ז מוזנים בטופס (ת״ז נשמרת כטקסט, 9 ספרות).
  ת״ז נבדקת לתקינות (ספרת ביקורת) גם בדפדפן וגם בשרת — **זו בדיקת תקינות, לא אימות זהות.**
  ההבחנה הזאת מוצגת במסך הניהול ובייצוא, לא למשתתפים.
* **ניסיונות ומבחן חוזר:** נספרים בשרת לפי ת״ז ומבחן (=מחזור). כל ניסיון נשמר בשורה נפרדת.
  הגשה מעבר למותר נשמרת בסטטוס ״חריגה״ ואינה נספרת. המנהלת מאשרת מבחן חוזר (כל אישור = ניסיון נוסף אחד),
  ויכולה לבטל ניסיון או להחזיר אותו לספירה.
* **פרטיות:** אין שום פונקציה ציבורית שמגלה אם ת״ז קיימת במערכת או מחזירה תוצאה לפי ת״ז.
  תוצאה אישית — רק לפי קוד אישור אקראי (12 תווים) שמתקבל בהגשה. ת״ז לא נשלחת בכתובות (URL),
  וכל פעולות הניהול מזהות נבחן לפי מזהה ההגשה. שארית סיכון: במצב ״הצגת תוצאות מיד״, מי שמגיש עם ת״ז
  שמיצתה את הניסיונות לא מקבל ציון על המסך — וזה עלול לרמוז שהת״ז כבר הגישה. במצבים האחרים התשובה זהה לכולם.
* **כללי המבחן:** ציון עובר, מספר ניסיונות, מועד הצגת תוצאות ו״איזה ציון קובע״ (הגבוה / האחרון) — נקבעים ע״י המנהלת.
  אין ערכי ברירת מחדל, והשרת לא מאפשר לפתוח מבחן לפני שכולם נקבעו ואושרו.
* **טופס סיום:** מופק רק אחרי אישור המנהלת, ורק למי שעבר לפי הציון הקובע. נשמר כרשומה (לא כקובץ); ה-PDF נוצר
  בדפדפן בזמן ההורדה. המשתתף/ת מקבל/ת אותו רק עם קוד האישור של הניסיון הקובע. ת״ז לא מודפסת כברירת מחדל.
  ביטול טופס שומר היסטוריה, והפקה מחדש יוצרת גרסה חדשה. יומן הפקות/ביטולים/צפיות נשמר (בלי ת״ז).
  קובץ החתימה ופרטי החותמת שמורים בטבלה פרטית (`private_assets`) — לא ב-GitHub ולא באחסון הציבורי.
  החתימה היא תמונה של חתימה בכתב יד, לא חתימה דיגיטלית מאומתת.
* **משוב אנונימי:** נשמר בלי שם ובלי שעה (תאריך בלבד), בטבלה נפרדת שאין לה שום קשר לנתוני המבחן.
* **מנהלת:** כניסה בדוא״ל וסיסמה ב-`admin.html`. ההרשאה נבדקת בשרת מול טבלת `admins`.
* **לו״ז ומצגות:** בעריכת הלו״ז אפשר לשייך לכל שיעור מצגת שכבר הועלתה (״שיוך מצגת״). באתר מופיע ליד השיעור אייקון
  ״פתיחת מצגת השיעור״. השיוך הוא לפריט המצגת, ולכן החלפת הקובץ לא שוברת את הקישור. מחיקת המצגת מנקה את השיוך.
* **קישורים:** אתר המדיניות, אינסטגרם ופייסבוק — בתחתית כל עמוד, נפתחים בלשונית חדשה. עריכה: ניהול ← חומרים וקישורים.
* **מילון מונחים:** קישור למילון חיצוני (ניהול ← מילון מונחים). כל עוד אין קישור — ״יעלה בהמשך״.
* **קבצים:** עד 50MB לקובץ (מגבלת השרת). מסמכים: pdf/pptx/docx/xlsx/תמונות. פודקאסטים: mp3/m4a/wav/ogg ו-mp4/mov/webm.
  סוג וגודל נבדקים לפני ההעלאה; העלאה שנכשלה לא נשמרת ולא מוצגת כהצלחה.
* **לו״ז ראשוני:** כל עוד המחזור לא סומן ״לו״ז מאושר״, האתר מציג ״לו״ז ראשוני – כפוף לעדכון״.

## מצבי פעולה
* **תצוגת הדגמה** — כש-`docs/js/config.js` ריק. פס כתום בראש העמוד. שום דבר לא משותף או מאובטח.
* **מערכת אמיתית** — אחרי מילוי כתובת הפרויקט והמפתח הציבורי ב-`docs/js/config.js`.

## הקמה חד-פעמית (Supabase)
1. supabase.com → New project (תוכנית Free). הפרויקט הקיים: אזור ap-northeast-2 (סיאול).
2. SQL Editor → להדביק את `supabase/schema.sql` → Run. אחר כך `supabase/seed.sql` → Run.
3. Authentication → Users → Add user → דוא״ל + סיסמה של המנהלת (Auto Confirm User).
4. SQL Editor:
   `insert into admins (user_id, email) select id, email from auth.users where email = 'כתובת@המנהלת';`
5. Authentication → Sign In / Providers → Email: לכבות **Allow new users to sign up** (אין צורך בהרשמה עצמית).
6. Project Settings → API Keys: להעתיק Project URL ואת המפתח הציבורי (anon / publishable) ל-`docs/js/config.js`.
   **לעולם לא** את service_role / secret key.
7. Authentication → URL Configuration → Site URL: `https://fortestudio26.github.io/taatz-course/`
